## 1. 主题与完成定义

> **v0.5 主题：自主性与集成——让模型能安全地派活、问人、用语义工具读工程、把大产物留在磁盘上。**

完成定义（可验收）：

1. 模型能用一个 `task` 工具把一段自包含的子任务交给子 agent，拿到结构化结果与独立成本，父上下文不被子 transcript 污染；
2. 模型在真正需要用户决策时能用 `ask` 提问，TUI 有对话框、headless 有明确降级；
3. 超过结果预算的工具输出可落到会话 `artifacts/`，`read_file` 能按行读回，模型不会"看到截断就再也拿不到"；
4. 工具启用/展示分离（`hidden`/`default_inactive`）与统一 `ToolRegistry.reconcile()`，MCP/skills/extensions 热更新走同一条路径；
5. LSP 至少在 Python/TypeScript 两个 server 上跑通只读 4 action + rename 的探针（条件项，见 §3.5）。

## 3. 每项的最小设计边界

### 3.1 `task` 子代理（P0）

- **模型面**：`task(prompt, name?, tools?, isolated?)` 单发同步；**不做** batch/async/worktree 隔离/结构化 yield（omp 那套契约面 3–5 倍成本）。
- **实现**：`build_task_tool(model, api_key, ..., child_tools)` 工厂；child = 新 `Agent`（同 model、只读工具集 + 独立 `ContextGuard`、独立 session？**默认不落 session**），递归深度 1（child 不注册 task）。
- **权限**：plan 模式直接拒绝；ask 模式下 child 的写/执行工具**不继承**父审批（child 只给只读集），避免嵌套弹窗。
- **结果**：`<task-result status duration cost>` + 输出（超限走结果预算/artifact）；父 `RunStatus`/telemetry 增加 `subagent_cost`（与父成本分开）。
- **验收**：child 能完成"读文件并总结"类任务；父上下文只收到 envelope；成本分开记录；plan 拒绝；测试覆盖 child 失败/超时/abort。

### 3.2 `ask` 工具（P1）

- **模型面**：`questions[{id, question, header?, options[{label, description?}], multi?, recommended?}]`（简化 omp）。
- **前端**：TUI 复用 framed `DialogScreen`（单选/多选）；REPL 用 input 交互；headless 返回"ask unavailable, proceed with conservative choice"（非 error 的降级）。
- **约束**：只允许真正需要用户决策的取舍；plan 模式可问；一次 2–5 个选项；UI 无超时（或沿用审批 120s？v0.5 定为**无超时**）。
- **验收**：TUI 选择回填答案；无 UI 降级可读；参数 schema/`approval="read"`。

### 3.3 artifact 落盘（P1）

- **触发**：结果预算截断时，完整结果写 `<session 目录>/artifacts/<tool>-<n>.txt`（或 `.json`）。
- **notice**：模型可见的截断提示尾部加 `artifact: <绝对路径> (N bytes)`；`read_file` 支持 `offset/limit` 回读（已有分页）。
- **保留**：每会话最多 N 个/总大小上限，超限回收最旧；失败降级为纯截断（不报错）。
- **验收**：>40KB 输出可落盘并回读；notice 路径正确；落盘失败不影响主流程；测试覆盖超限回收。

### 3.4 工具注册/热更新统一（P1）

- `AgentTool.hidden` / `default_inactive`（内核只声明，装配层决定）；`ToolRegistry`：active set、变更通知、`reconcile()` 重建 prompt+agent.tools。
- 统一 MCP refresh、skills reload、extensions reload 到 `Runtime.reconcile()`；TUI 增加与 REPL 等价的热更新入口。
- **验收**：hidden 工具不进 prompt/模型可调用集；`/reload`、MCP 后补连接、extension 变更走同一路径；工具集合变化只重画一次 prompt。

### 3.5 LSP 最小版（P1 条件项）

- **先探针后全量**：先支持 `pyright`/`typescript-language-server` 各一个，4 个只读 action（diagnostics/symbols/references/definition）+ `rename`。
- 子进程 + JSON-RPC；server 按扩展名映射、PATH 探测；缺 server → 动作报"server not installed"而不是工具消失。
- 审批：只读 action = read 档；rename = write 档；写后延迟诊断可作为 P2 增强。
- **验收**：两个 server 上 5 个 action 的集成测试（可跳过环境缺失）；超时/崩溃隔离；不引入新 pip 依赖。
- **风险**：外部二进制策略（与"最小纯 Python"的张力）——若探针不达标，本项降级为 v0.6。

### 3.6 MCP 重连重试（P2）

- `call_tool` 遇传输层错误 → 关闭连接、`_connect` 一次、重发一次；仍失败返回可读错误。
- **验收**：fake server 断线重连测试；不重试业务错误（`isError` 结果不算）。

### 3.7 github 只读子集（P2 条件）

- `github` 工具 4 个 op：`pr_view`/`pr_diff`/`pr_checks`/`run_logs`；`gh` 不存在则不注册；全部 read 档。
- **验收**：`gh` 缺失时工具不存在；只读 op 在 plan 下可用；输出有上限。

### 3.8 checkpoint/rewind（P2 条件）

- 模型可见工具：`checkpoint(goal)` 标记、`rewind(report)` 用报告替换中间探索上下文；依赖 compaction 管线已有能力。
- **验收**：rewind 后上下文只保留报告与 checkpoint 前内容；失败可回退（不损坏 session）。

## 4. 明确不做（延续 v0.4 裁决）

browser、computer、debug/DAP、IDA、security_scan、tts、generate_image、eval 内核（py/js + 工具桥）、
memory backend、managed skill 自改写、goal/vibe/loop、`xd://` 设备协议、BM25/lazy discovery、
speculation、`openArgStream`、live steering、hashline/5 种 edit 模式、find 语义搜索、

理由见 `10-tools-gap.md` §6.5（与"纯 Python + httpx 单运行时依赖 + 最小内核"冲突，或属于 omp 的账号/垂直场景成本）。

## 5. 需要拍板的决策（开工前）

1. **子代理权限模型**：child 默认只读集（推荐）还是继承父工具集但写操作升级为自动拒绝？child 的失败/超时如何向父呈现？
2. **子代理成本展示**：只进 telemetry，还是 TUI 状态带单独一段（`subagent_cost`）？
3. **artifact 目录布局/保留策略**：`<session 目录>/artifacts/` 还是 `~/.zenagent/artifacts/<session>/`？每会话上限（数量/字节）？
4. **LSP 外部二进制政策**：PATH 缺失时静默不注册（推荐）还是报错提示安装？是否接受可选外部依赖作为 v0.5 条件项？
5. **`ask` 在 plan 模式是否允许**：允许（推荐，计划确认需要用户输入）还是沿用"plan 只读不交互"？
6. **hidden/default_inactive 的默认集**：哪些工具默认隐藏（比如未来 github/artifact 工具），是否允许设置覆盖？
