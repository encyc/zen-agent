# pyagent S2 计划：可扩展（10 个任务）

> **上游：** [功能盘点](../feature-inventory.md) 的 S2 分期（MCP / skills / templates / 自定义 provider / 扩展 / 热重载 / packages / 主题 / 键位 / 工具白名单）。
> **前置：** S1 的 12 个任务与 E0 行为评测已完成（407 tests + 13 eval cases）。
> **约束：** 内核仍只依赖 `httpx`；`rich`/`prompt_toolkit` 留在 cli extra；所有新逻辑必须有离线单测；能加 eval 用例的加一条。

**执行状态（2026-10-29 22:15）：T1–T9 ✅**（494 tests green）。真机验证：T1 `--cwd`/`--trace`；T2 真实 filesystem server 握手/14 工具/往返/回收；T3 模型经 CLI 调用 `mcp__files__read_text_file` 读到文件，且**「启动时连不上、之后才起来」的 server 在同一 session 内可重连并热替换工具**。T4 真机：模型经 `read_skill` 加载本地 skill 并产出约定 token（并把 read_skill 修正为读类工具，无需 --yes）。T5 真机：REPL `/review note.txt` 展开模板并产出文件内 token；T6 真机：config.toml 覆盖内置 deepseek provider 后请求成功，doctor 显示覆盖 warning。T7 真机：扩展注册的工具被调用、prompt 规则被遵守。T8 真机（单测覆盖）：会话中途新增 skill → `/reload` 后可见。T9 真机：`--read-only` 下写文件被拒、目录保持为空。其余 1 项（theme/keybindings）待做。

**目标：** 让 pyagent 从"能用的 coding agent"变成"可被自己改造的 harness"：接得上 MCP 工具生态、读得懂 skills 与 prompt 模板、能注册自己的 provider 与扩展、能一键重载、有明确的工具授权策略、界面可调。

## Global Constraints（新增）

- **不引入 MCP 官方 SDK**：自己实现 JSON-RPC 2.0 子集（stdio + Streamable HTTP），与"手写传输层"的项目定位一致。
- **扩展与 skills 默认不自动加载**：必须显式启用（config 或 `--extensions`），加载失败只警告不崩。
- **MCP 工具与内置工具同名时**：内置优先，MCP 工具加 `mcp__<server>__` 前缀避免冲突。
- **授权先于执行**：任何 MCP/扩展工具都要过现有 `PermissionGate`（它们不是"读类"，默认需要确认/`--yes`）。
- **热重载只在空闲时执行**：run 中 `/reload` 提示稍后。

## Review Focus

1. **MCP 进程生命周期**：子进程泄漏、stdio 阻塞、退出时清理（每个 server 一个 client，`close()` 必须被调用）。
2. **MCP 错误隔离**：server 崩溃/超时/坏 JSON 只能让该工具变 is_error，不能拖垮 loop。
3. **扩展沙箱边界**：扩展能拿到 Agent 内部多少？v1 只暴露注册接口，不给任意 hook 逃逸。
4. **skills/templates 注入有界**：与 AGENTS.md 一样有大小上限，避免污染上下文。
5. **工具白名单不能绕过危险命令策略**：allowlist 只做额外收紧，不解除 T2 的黑名单。

## T1: trace 落盘 + `--cwd`

**Why:** 调试 agent 需要看"它到底调了什么、参数是什么、结果如何"；这也是将来接 kbench 的原始素材。

**Files:** Create `pyagent/trace.py`；Modify `pyagent/cli/main.py`（`--trace PATH`、`--cwd PATH`）、`pyagent/cli/repl.py`（同）；Test `tests/test_trace.py`、`tests/test_cli.py`

**Interfaces:**
- `@dataclass TraceRecord: ts: float, type: str, tool: str | None, args: dict | None, ok: bool | None, duration_ms: int | None, turn: int`
- `class TraceRecorder`: 订阅 `AgentEvent`，只记 `turn_start` / `tool_execution_start` / `tool_execution_end`（start 与 end 用 `tool_call_id` 配对，end 补齐 ok/duration）；`records -> list[TraceRecord]`；`write_jsonl(path) -> None`。
- `def make_trace_subscriber(path: Path) -> TraceRecorder`：构造并立即打开文件（追加写、每行 flush）。
- `--cwd PATH`：启动前 `os.chdir`；路径不存在/不是目录 → stderr + 退出 1；**必须在 context files 发现之前**执行。
- `--trace PATH`：headless 与 repl 都接；写入 JSONL（一行一条）。

- [ ] **Step 1: 失败测试** —— 用 fake stream 驱动一次工具轮，断言 records 含 start/end 且 ok/duration 正确；JSONL 每行可 `json.loads`；`main(["-p","hi","--cwd",str(tmp)])` 下 patched `_build_agent` 里 `Path.cwd() == tmp`；坏 `--cwd` 返回 1。
- [ ] **Step 2–4:** 实现 → 全绿。
- [ ] **Step 5:** Commit `feat: jsonl trace of tool turns and a --cwd flag`

## T2: MCP 客户端核心

**Why:** MCP 是工具生态的事实标准；自己实现一遍 JSON-RPC 也符合项目"手写传输层"的定位。

**Files:** Create `pyagent/mcp/__init__.py`、`pyagent/mcp/client.py`、`pyagent/mcp/config.py`；Test `tests/test_mcp_client.py`

**Interfaces:**
- `class McpError(Exception)`；`class McpTimeout(McpError)`。
- `class McpClient`:
  - `__init__(name, transport)`；`async def start()`：握手 `initialize`（protocolVersion `2024-11-05`，capabilities `{}`）→ `notifications/initialized`。
  - `async def list_tools() -> list[McpTool]`（`McpTool(name, description, input_schema)`）。
  - `async def call_tool(name, arguments, timeout_s=60) -> McpCallResult`（`content: list[dict]`、`is_error: bool`）。
  - `async def close()`：关闭 stdin、terminate 子进程、等待退出（超时则 kill）。
- `class StdioTransport`：`asyncio.create_subprocess_exec(command, *args, stdin/stdout=PIPE, env=...)`；按行读写 JSON；`request(method, params)` 用递增 id，`pending: dict[int, Future]`，读循环分发；未知/通知直接忽略并记 trace。
- `class HttpTransport`：Streamable HTTP（`POST {url}`，`Accept: application/json, text/event-stream`；响应可能是 JSON 或 SSE，单个 `data:` 事件即结果）；headers 可配。
- `def load_mcp_config(path: Path | None = None) -> dict[str, McpServerConfig]`：`~/.pyagent/mcp.json`（或 config.toml `[mcp]`，二选一，实现一个），server 形态 `{"command": [...], "env": {...}}` 或 `{"url": "...", "headers": {...}}`。

- [ ] **Step 1: 失败测试** —— 用一个 Python 脚本充当 stdio server（`tests/fixtures/mcp_echo_server.py`），实现 `initialize`/`tools/list`/`tools/call`；断言握手、列工具、调用回显、未知方法报错、server 崩溃 → `McpError`、`close()` 后进程消失。HTTP 用 `httpx.MockTransport` 测 JSON 与 SSE 两种响应。
- [ ] **Step 2–4:** 实现 → 全绿。
- [ ] **Step 5:** Commit `feat: minimal mcp client over stdio and streamable http`
