# zenagent S3 计划：生态与集成（10 个任务）

> **上游：** [功能盘点](../feature-inventory.md) 的 S3 分期。
> **前置：** M1–M4、S1（12 任务）、S2（10 任务）全部完成；510 tests + 18 条行为评测全绿。

**执行状态（2026-10-29 23:55）：S3 全部完成 T1–T10 ✅**（565 tests green）。项目更名为 **ZenAgent**（包名 `zenagent`，CLI `zen`，配置目录 `~/.zenagent`）。T1 真机导出会话；T2 真机统计 2 个真实会话（含 cache 命中）。其余 8 项待做。

**目标：** 让 zenagent 能**被别的程序用起来**、能把会话**带走**、能在真实环境里**排障**，并补齐协议覆盖与重试质量。

## Global Constraints

- 内核仍只依赖 `httpx`；导出/telemetry/crash log 不引入新依赖（HTML 手写转义）。
- 所有输出格式（导出、指标、RPC）**版本化并稳定**，未知字段忽略、缺字段有默认。
- 导出与指标是**只读**操作：绝不修改会话文件。
- 新协议适配器必须复用现有的 `StreamFn` 契约与同一套 fixture 回放测试。

## Review Focus

1. **HTML 导出必须转义**：模型输出里的 `<script>`、`&`、引号不能变成可执行标记。
2. **指标容错**：损坏的 session 行、缺 usage 的旧会话不能让 `usage` 崩。
3. **RPC 不得吞事件**：stdout 一行一个 JSON，必须是合法 JSON（不能混入日志）。
4. **重试不能重放已产生的工具副作用**：message 级重试只能重发「未开始执行工具」的那一轮。
5. **telemetry 默认关闭**：开启时才写盘，且不记录 prompt 原文（只记 token/耗时/工具名）。

## T3: message 级重试

**Why:** 现在只有 transport 层按状态码重试；provider 返回 200 + error body、或流内 error，都不会重试。

**Files:** Create `zenagent/retry.py`；Modify `zenagent/agent/loop.py`、`zenagent/cli/main.py`；Test `tests/test_retry.py`

**Interfaces:**
- `is_retryable(message: AssistantMessage) -> bool`：`stop_reason=="error"` 且文案匹配可重试集合（timeout/reset/5xx/overloaded/rate limit），排除 quota/401/403/400。
- `async def call_with_retry(stream_fn, model, messages, tools, options, *, retries=2, base_delay=0.5, sleep=asyncio.sleep) -> AsyncIterator[AssistantEvent]`：仅当**上一轮没有执行任何工具**时允许重试（loop 传入 `allow_retry` 标志）；退避期间 abort 立即返回 aborted 终局。
- loop 在请求前判断是否允许重试（`turns>0` 且上一轮无工具调用 → 允许）。
- CLI `--retries N`（默认 0 保持现状）。

- [ ] **Step 1:** 失败测试：可重试错误 → 第二次成功；不可重试 → 立即返回；达到上限 → 返回最后一次 error；abort 打断退避；有工具副作用的轮次不重试。
- [ ] **Step 2–4:** 实现 → 全绿。
- [ ] **Step 5:** Commit `feat: message-level retry for transient provider failures`

## T8: RPC 模式

**Why:** 编辑器/桌面壳需要一个进程级接口，而不是解析终端输出。

**Files:** Create `zenagent/cli/rpc.py`；Modify `zenagent/cli/main.py`；Test `tests/test_rpc.py`

**Interfaces:**
- 一行一个 JSON。请求：`{"type":"prompt","id":str,"text":str}`、`{"type":"cancel","id"}`、`{"type":"status","id"}`、`{"type":"shutdown","id"}`。
- 事件：`{"type":"event","event":{...精简 AgentEvent...}}`；结果：`{"type":"result","id","ok","text","usage","termination"}`；错误：`{"type":"error","id","message"}`。
- `class RpcServer(agent, reader, writer)`：单 run 互斥；`run()` 循环读行；未知 type → error；坏 JSON → error 不退出。
- CLI `zenagent rpc [--model ...]`（stdout 只写协议，日志走 stderr）。

- [ ] **Step 1:** 失败测试（注入 fake agent/stream + StringIO）：prompt → 事件 + result；cancel 生效；坏 JSON 返回 error 且继续；shutdown 退出；stdout 每行可 `json.loads`。
- [ ] **Step 2–4:** 实现 → 全绿。
- [ ] **Step 5:** Commit `feat: jsonl rpc mode for embedding`
