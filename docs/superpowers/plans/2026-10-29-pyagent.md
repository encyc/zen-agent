# pyagent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用纯 Python（3.15+，asyncio）从零实现最小 coding agent `pyagent`：统一 LLM 数据模型与流式事件协议、两个协议适配器（openai-completions 含 zai/deepseek 方言、anthropic-messages）、agent loop、七个文件/命令工具、交互式 REPL 与 headless 入口。

**Architecture:** 五层严格向下依赖：`types`/`events`（数据模型与事件契约）→ `providers`（适配器 + provider 配置 + 目录，StreamFn 永不抛异常）→ `agent`（`agent_loop` 纯函数 + `Agent` 有状态壳 + 钩子，工具失败一律转 is_error 结果）→ `tools` → `cli`（REPL + headless，权限门是 CLI 层的 before_tool_call）。会话为 JSONL 追加日志。

**Tech Stack:** Python 3.15+、uv、httpx（内核唯一运行时依赖）、prompt_toolkit + rich（CLI extra）、pytest + pytest-asyncio（dev）。

**Spec:** `docs/superpowers/specs/2026-10-29-pyagent-design.md`（含从 pi-ai 1.4.0 核实的 wire 事实小节——适配器任务的依据）

## Global Constraints

- `requires-python = ">=3.15"`，uv 管理项目与依赖；单包 `pyagent`，单仓库。
- 内核（`pyagent.types/events/providers/agent/tools`）运行时依赖只有 `httpx`；`prompt_toolkit`/`rich` 只在 `pyagent.cli` 且作为 `[project.optional-dependencies] cli`。禁止引入任何厂商 SDK 或 agent 框架。
- 依赖方向严格向下：`providers` 不得 import `agent`/`cli`；`agent` 不得 import `cli`。pyflakes/Ruff import 检查通过（ruff 作为 dev 依赖仅做 import 排序与未使用导入检查，不做风格警察）。
- StreamFn 契约：`stream(...)` 永不抛异常，一切失败（网络、4xx/5xx、超时、解析错）以携带 `stop_reason="error"` 或 `"aborted"` 的终局 AssistantEvent 表达。
- 取消契约：abort 是协议内状态，不是 `BaseException`。协作取消用 `pyagent.events.Aborted(Exception)` 表达，由 `safe_stream` 转成 `error(reason="aborted")` 终局事件；`asyncio.CancelledError` 只表示真实 task 取消，**禁止伪造**。
- thinking 档位：合法值为 `None`（关闭）与 `"off" | "low" | "medium" | "high"`。`"off"` 与 `None` 等价，loop 与 adapter 各归一一次；其它值抛 `ValueError`（库契约，不静默发脏字段）。
- 工具执行：`arguments_error` 非空、参数校验失败、未知工具、assistant `stop_reason=="length"`——一律**不调用 `execute`**，转 `is_error=True` 的 ToolResult，loop 不中断。
- 工具契约：`execute` 抛异常、参数不合法、未知工具——一律转 `is_error=True` 的 ToolResult，loop 不中断。
- 单元测试全部离线（SSE 用 fixture 重放）；只有 Task 11/14 的验收脚本与 `scripts/capture_sse.py` 触真实 API。
- 目录/会话/配置路径：目录 YAML 打包在 `pyagent/catalog.yaml`；会话 `~/.pyagent/sessions/`；配置 `~/.pyagent/config.toml`。
- 每个任务以 green 测试 + commit 结束；commit message 用 conventional 风格（`feat:`/`test:`/`chore:`）。

## Review Focus

以下输入类/失败模式最可能咬到真实使用者，每条已钉在归属任务的测试里：

1. **SSE 行跨网络 chunk 断裂**（一行 `data:` 分两次到达）——重放时按行拼接后再解析，不许丢半行。→ Task 4 测试。
2. **流中途网络断开**（首 token 之后连接 reset）——必须以 `stop_reason="error"` 终局事件收尾，不许向上抛。→ Task 8 测试。
3. **模型输出烂 JSON 工具参数**——降级为 `arguments={}` + `arguments_error` 描述，loop 继续跑完该轮。→ Task 7 测试。
4. **`edit_file` 替换串非唯一匹配**——返回 is_error 结果说明匹配数，不许改文件。→ Task 12 测试。
5. **会话 JSONL 尾行残缺**（进程被杀留下半行）——`--resume` 跳过残缺行并 stderr 警告，不许崩。→ Task 15 测试。
6. **abort 竞态**——loop 顶部已检查 abort，但 abort 若在「检查之后、transport 建连之前」触发，`post_stream` 抛出的 `CancelledError` 会以 `BaseException` 穿透 `safe_stream` 与 `agent_loop`（已实测复现：事件流走完 `agent_end` 后仍抛出）。→ Task 9A 测试。
7. **`stop_reason=="length"` 带工具调用**——T9 现有实现会把这条 assistant 消息（含 `tool_call` 块）原样写进 transcript，但**不追加任何 tool result**。transcript 因此出现「有 `tool_calls` 无对应 tool 消息」，下一轮请求会被 OpenAI 兼容端点直接拒绝（已实测复现：`dangling tool_calls: True`）。→ Task 9A 测试。
8. **`on_update` 生命周期**——工具 settle 之后再调用 `on_update` 必须被丢弃，不得发事件；否则 UI 会收到迟到的残影。→ Task 9A 测试。

**Decisions（binding，后续任务不得推翻）:**

1. **Abort 是普通异常。** `events.Aborted(Exception)`；`transport.post_stream` 在「请求发起前已 abort」与「退避等待中被 abort」时抛它（退避用 `asyncio.wait` 同时等 abort token，替代裸 `asyncio.sleep`）；`safe_stream` 捕获 `Aborted` → 产出 `error(reason="aborted")` 终局事件，与其它 `Exception` 的 `reason="error"` 区分开。`asyncio.CancelledError`（`BaseException`）继续穿透——它只表示真实 task 取消。
2. **thinking 档位在 adapter 侧也守一道。** `build_params` 接受 `None | "off" | "low" | "medium" | "high"`；`"off"` 视同关闭（与 `None` 产出完全相同的 body），其它值抛 `ValueError`。loop 侧已归一（`config.thinking in (None, "off")`），此处是为**库的其它调用方**兜底。
3. **`on_update` 进入工具契约。** `AgentTool.execute(tool_call_id, params, abort, on_update)`，`on_update(partial: ToolResultAgent) -> None`；loop 转成 `AgentEvent(type="tool_execution_update", tool_call_id=..., tool_name=..., partial_result=...)`。工具 settle 后到达的 update 一律丢弃（用 `accepting` 标志，finally 置 False）。`ToolResultAgent` 增 `details: dict = field(default_factory=dict)`（UI 用，不进 LLM 上下文）。
4. **`length` 截断规约。** assistant `stop_reason=="length"` 且含 tool 调用时：**整批**不执行，每条产出 `is_error=True` 的结果，文案说明「输出被截断、参数可能不完整，请重新发起」。目的有二：不执行半截参数；**且不让带 `tool_calls` 的 assistant 消息无对应 tool result 留在 transcript 里**（后者会让下一轮请求被端点拒绝）。
5. **最小参数校验。** `pyagent/agent/validate.py` 的 `validate_arguments(schema: dict, args: dict) -> str | None`：只校验顶层 `type=="object"`、`required` 列出的键存在、顶层 `properties` 声明的 `type`（string/number/integer/boolean/object/array，允许 `int` 满足 `number`）匹配。不做递归、`anyOf`、`format`、默认值填充。校验在 `before_tool_call` **之前**（pi 同序），失败即 is_error、`execute` 零调用。
