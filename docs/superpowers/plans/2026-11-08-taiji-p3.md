# Taiji P3 — 调度台（Panel v2）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把只读的泳道图 panel 重造为可操作的调度台：按"人的介入程度"分组展示 worker 生命周期，每个状态都有对应动作（快捷答复/合并/打回/插话/终止/恢复/peek），动作经新 RPC 写 op 直连 supervisor。

**Architecture:** 读侧收敛为一个 `taiji board` op（supervisor 状态 + diffstat + attention options + slots + router busy），写侧 `message/merge/kill/peek` 四个 op 直连 `existing_taiji()` 进程单例；宿主持锁时 boot 即急切构造 supervisor。worker 运行中插话进**信箱**，回合链尾部续跑。desktop 侧 `taijiBoard.ts` 纯分组逻辑 + `TaijiPanel.tsx` 调度台渲染，泳道图代码退役。

**Tech Stack:** 与 P0–P2 相同——Python 3.11+ / asyncio / subprocess git；React 18 / zustand / CSS Modules；node:test + Playwright。

**Spec:** `docs/superpowers/specs/2026-11-07-taiji-design.md` 附录 C（调度台方案、交互总表、决策记录）。

## Global Constraints

（沿 P2 全量）：零新依赖；git subprocess 带超时；注册表原子写；import DAG 不许向上（taiji 不 import cli）；`PROTOCOL_VERSION=2` 不变，`REQUEST_KINDS`（types.ts）仍镜像 rpc.py 的 kind 集（kind 不增不减）；desktop 只用 design token + i18n 双字典（zh+en 同步）；注册表不新增字段（attention 仍是 str JSON，options 装进 attention 对象内部）。

## Review Focus

1. **插话竞态**：message 落在回合置终态与 `_settled` 清理之间 → `_settled` 必须只清自己那格映射，否则后续 kill 取消不到在飞回合（P2 kill 竞态复发）。→ Task 1 测试 `test_message_during_settling_keeps_turn_tracking`。
2. **信箱泄漏**：kill/rollback 后信箱残留会话给下一回合 → kill 与 rollback 清空 inbox。→ Task 1 测试。
3. **attention 选项畸形**：questions/options 缺失或非 dict → `options: []` 不炸；上限 4。→ Task 3 测试。
4. **peek 撕裂行**：JSONL 尾部半行/坏行跳过不炸；role 缺失行跳过。→ Task 3 测试。
5. **board 无 supervisor**：worker 子进程/linked worktree 的宿主里 `existing_taiji()` 为 None → `active:false` 空板而非异常。→ Task 4 测试。
6. **合并失败可读**：merge 返回 False 时 op 必须带 `merge_block_reason` 的中文原因（面板直接展示）。→ Task 4 测试。

### Task 1: supervisor 信箱 + slots 状态 + 回合追踪精确清理

**Files:**
- Modify: `zenagent/app/taiji/supervisor.py`
- Test: `tests/test_taiji_supervisor.py`（追加）

**Interfaces:**
- Produces: `TaijiSupervisor.message(name, text)`——status=="running" 时不再 raise，而是追加进 `self._inbox[name]` 并原样返回 record（status 仍 running，即"已排队"信号）；`_run_turn` 尾部（emit 之后、且 status 不在 `("killed","merged")`）pop inbox，非空则 `_start_turn(record, "\n\n".join(inbox), resume=record.session or None, rollback_on_start_failure=False, use_slot=False)`。`kill()` 与 `_rollback()` 清 `self._inbox.pop(name, None)`。

- Produces: 模块函数 `existing_taiji() -> TaijiSupervisor | None`（返回 `_SINGLETON`，不构造）。
- 测试：message 到 running worker → 不 raise、信箱有话、回合结束后续跑且文本是合并值；kill 运行中 worker → inbox 清空且无续跑；`_settled` 竞态（手工把 `_turns[name]` 换成新任务后旧任务 settle，新映射保留）；slots_state 在 max_workers=2 下三连 spawn 的 busy/queued 计数。

### 偏离计划的决定

- **T5+T6 合并为一次提交**：类型切换会让旧 panel 瞬间编译失败，两个任务无法各自形成可编译快照；一次提交保住"每个提交都绿"的项目约定。
- **`queued` 语义修正**（T4 实现中发现）：计划写的是"`record.status == 'running'` 即 queued"，但 message 直发新回合后 status 也是 running——面板无法区分"进了信箱"和"已开跑"。改为 op 在 await 前原子快照 worker 状态（同一事件循环内无 yield，无竞态）。
- **RPC ops 内联 await**（非 create_task）：`_handle_line` 本身 async，内联保证同 request 的应答顺序，测试 helper 也不必排空任务队列。
- **T2 测试修复两处**：`git_status` 的 TTL 缓存吃掉脏树变异（`reset_cache()`）；`git checkout task/ds` 被 worktree 占用静默失败（改用第三分支模拟基分支偏移）。
